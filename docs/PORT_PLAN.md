Составлен 07.10.2026. Решения владельца на эту дату:

## 1. Что берём

Исходники — `orig/bbc/cassette` (репозиторий Марка Моксона, код Белла и Брабена с построчными комментариями;
описание — https://elite.bbcelite.com/cassette/). Один файл `elite-source.asm`, 38 278 строк, ассемблер 6502.

| часть | байт | где на BBC |
|---|---|---|
| код игры (ELTA…ELTG) | 18 170 | &0F40–&5639 |
| модели, 13 типов (SHIPS + PYTHON) | 2 502 + 256 | &563A–&5FFF, &7F00 |
| словарь текста (QQ18) | 1 024 | &0400 |
| **всего в памяти** | **21 952** | |
| блоки кораблей и списки отрезков (K%) | 1 088 | &0900 |
| слоты и переменные (WP) | 500 | &0D40 |
| пилот и звёздная пыль (T%) | 114 | &0300 |
| нулевая страница игры | 193 | |
| экран: обзор 256×192, 1 бит + панель 128×56, 4 цвета | 7 936 | &6000–&7EFF |

В игре 9 414 команд процессора, около 470 процедур. По разметке автора комментариев: арифметика 48, текст 36,
вселенная 31, печать кораблей 30, панель 27, полёт 25, линии 23, главный цикл 22, геометрия 17, рынок 17,
движение 16, клавиатура 15, планеты 15, тактика 13, сохранение 11, остальное — по 2–9.

### Решающие наблюдения

1. **К железу BBC игра почти не обращается.** Три вызова OSBYTE, два OSWORD (звук), один OSFILE (сохранение),
   полтора десятка обращений к VIA и видеосхеме — всё в обработчике кадра (разделение экрана на два режима),
   опросе клавиш и загрузке. Значит, игру можно гонять в голом ядре 6502 с заглушками, без эмулятора BBC.
2. **Печать — прямо на экран, исключающим ИЛИ.** Объект рисуется, отрезки запоминаются в его списке; следующий
   кадр стирает их повторной печатью и рисует новые. Буфер кадра не нужен — то, что требуется ванильному Вектору.
3. **Обзор 256×192 совпадает с шириной экрана Вектора.** Обзор и панель (56 строк) вместе дают 248 строк из 256.
   Обзор можно сделать точка в точку как на BBC и сверять снимками.
4. **Арифметика восьмиразрядная**, без таблиц логарифмов (они появились позже, в 6502SP). Ложится на i8080 без
   потерь разрядности; ловушка одна — у 6502 перенос при вычитании обратный.
5. **В репозитории лежит готовый листинг** (`3-assembled-output/compile.txt`) с адресами всех меток и эталонные
   двоичные файлы без защиты (`*.unprot.bin`). Собирать оригинал не обязательно; BeebAsm на машине нет.

## 2. Способ: настоящий код как эталон

Отдельную модель игры на JS **целиком не пишем**. Эталон — сам код BBC, исполняемый в ядре 6502 под Node:
`tools/oracle/`. Он даёт то же, что дала бы модель, но без риска ошибиться при пересказе:

- **прогон игры** по сценарию клавиш с выгрузкой состояния на каждом проходе главного цикла (блоки кораблей K%,
  слоты, пилот T%, генератор случайных чисел RAND, экран);
- **вызов одной процедуры** с заданным входом: память и регистры до — память и регистры после. Это главный
  инструмент: каждая процедура на i8080 сверяется со своей парой на 6502 на тысячах входов.

На JS пишется только то, чего у BBC нет или что на Векторе иное: панель 256 точек шириной, раскладка экрана,
цвета, клавиши, позже — расширения и русский текст. Это профиль Вектора (`web/`), его показываем владельцу до
переноса на i8080 — как страницу-игру в tankwars: обзор и логику считает настоящий код 6502, панель и цвет —
новый слой.

Этап «сначала Z80» отпадает: переводить с Z80 нечего, код пишется сразу для i8080 (sjasmplus `--i8080`, мнемоника
Z80-подмножества, как в tankwars и cat).

### Соответствие 6502 → i8080

| 6502 | i8080 |
|---|---|
| A | A |
| X, Y | по месту: B/C/D/E или ячейка; индексная адресация — через HL |
| нулевая страница | страница переменных по фиксированному адресу, порядок тот же, что на BBC |
| `(INF),Y`, `(XX0),Y` — блок корабля и модель | HL = указатель + смещение; частые поля — копия блока в рабочую область (на BBC это INWK, она уже есть) |
| перенос при `SBC` (обратный) | `sub/sbb` с поправкой условий перехода — проверяется парными тестами |
| `BIT`, флаг V | явные проверки |
| само­модифицирующийся код | оставляем, где он есть |

Раскладка переменных на Векторе повторяет BBC (то же смещение внутри рабочих областей). Тогда состояние
сравнивается побайтно без таблиц пересчёта.

## 3. Память и экран Вектора

```
#0000–#00FF  RST, вектор прерывания
#0100–…      код
…            модели, словарь, шрифт
…            рабочие области: «нулевая страница», T%, K%, WP (около 2 КБ)
…–#BFFF      стек
#C000–#DFFF  плоскость 1 ┐ 256×256, 4 цвета
#E000–#FFFF  плоскость 2 ┘
```

Плоскости #8000 и #A000 заняты программой; палитра строится так, что их биты на цвет не влияют.

### Бюджет (оценка, не замер)

| часть | BBC | Вектор |
|---|---|---|
| код игры | 18 170 | 26 000–31 000 (×1,4–1,7) |
| модели | 2 758 | 2 758 |
| словарь | 1 024 | 1 024 |
| шрифт (на BBC он в ПЗУ машины) | — | 768 |
| слой Вектора: прерывание, палитра, клавиатура, ВИ53, панель | — | 2 000 |
| рабочие области и стек | 2 033 | 2 300 |
| **итого** | **21 952 + 2 033** | **35 000–40 000 из 48 000** |

Запас 8–13 КБ — место под расширения. Коэффициент роста кода — главная неизвестная; он станет известен после
арифметики (48 процедур), это первая же задача на i8080.

### Экран

- **Экран как на BBC** (решение владельца 07.10.2026): обзор двухцветный, панель четырёхцветная.
- Обзор 256×192 — точка в точку как на BBC, рисуется в одной плоскости; это позволяет сверять снимки экрана с
  эталоном.
- Панель — 56 строк под обзором. На BBC это режим 5: 128 точек двойной ширины в четырёх цветах, на всю ширину
  экрана. На Векторе — те же точки двойной ширины в двух плоскостях: картинка панели переводится из файла BBC
  скриптом, процедуры приборов и сканера повторяют логику BBC и сверяются с эталоном по экрану.
- Разделения экрана на два режима (на BBC — работа в обработчике кадра) на Векторе нет: оба режима заменяет одна
  палитра из четырёх цветов.
- Цвет в обзоре (солнце, планета, лазер во второй плоскости, как у Master) — расширение R1.
- Палитра меняется целиком при смене экрана (полёт, станция, карта) и для вспышек (энергобомба, гибель).
- Столбцовая память Вектора (адрес = плоскость + X/8·256 + (255 − Y)) — процедуры точки, отрезка и
  горизонтальной линии пишутся заново; результат обязан совпасть с BBC до точки.

## 4. Этапы

| № | этап | что появляется | как проверяется |
|---|---|---|---|
| P0 | Эталон | ядро 6502 под Node, образ памяти игры после загрузки, заглушки системы BBC, сценарий клавиш, выгрузка состояния и экрана, вызов отдельной процедуры | снимок заставки совпадает со снимком из настоящего эмулятора BBC; два прогона одного сценария дают одно состояние; записаны эталонные сценарии: заставка, взлёт, полёт, бой, стыковка, торговля, прыжок, гибель |
| P1 | Каркас Вектора | карта памяти, прерывание кадра, палитра, клавиатура, шрифт, точка, отрезок (LOIN), горизонтальная линия (HLOIN) | экран Вектора после серии случайных отрезков = экран эталона; замер тактов на отрезок |
| P2 | Арифметика | умножения, деления, корень, арктангенс, синусы, геометрия (65 процедур) | каждая процедура против 6502 на тысячах входов, включая края; **замер коэффициента роста кода** |
| P3 | Печать объектов | корабль с невидимыми гранями и списком отрезков (LL9), окружности, планета, солнце, звёздная пыль, взрыв | **М1 — вращение корабля на заставке**: экран = эталон кадр в кадр; замер кадров в секунду |
| P4 | Полёт | главный цикл, движение, тактика, появление кораблей, лазер и ракеты, панель, сканер, компас, стыковка, прыжок | **М2**: сценарии полёта и боя — состояние = эталон на каждом проходе цикла |
| P5 | Станция | словарь и печать текста, галактики, рынок, оборудование, карты, сведения о планете, статус | **М3 — игра целиком**: сценарий «купил, взлетел, прыгнул, сел, продал» = эталон |
| P6 | Доводка | звук ВИ53, сохранение, заставка, джойстики, Турбо+ | MiSTer, инструкция, **выпуск 1.0 «кассета»** |
| P7 | Расширения | см. §5 | у каждого — своя задача и своя проверка |

P1 и P0 идут параллельно. P2 можно делить между исполнителями: процедуры независимы, тест на каждую готов из
эталона. P3–P5 — по очереди. Звук (P6) можно начинать после P1.

### Проверка по ходу

- После каждого рубежа — показ на MiSTer.
- Скорость меряется с М1. Кассетная версия рассчитана на 6502 при 2 МГц; i8080 при 3 МГц с тактами Вектора
  медленнее. Ориентир — число тактов 6502 на проход цикла из эталона против тактов i8080.

## 6. Риски

| риск | чем грозит | что делаем |
|---|---|---|
| Скорость | мало кадров в бою | замер на М1; горячие места — умножение, печать отрезка, поворот вершин — пишутся под i8080 руками, не пересказом 6502; упрощения из версии Electron; Турбо+ как быстрый вариант |
| Рост кода больше 1,7 | меньше места под расширения | замер на P2; 1.0 входит и при ×2 (36 КБ кода + 9 КБ остального) |
| Обратный перенос и флаги 6502 | тихие ошибки в арифметике и условиях | парные тесты каждой процедуры, а не только прогоны игры |
| Привязка ко времени | эталон и порт расходятся из-за разной длительности кадра | сверка по проходам главного цикла, а не по кадрам; найти в коде все места, зависящие от счётчика кадров и таймера, — в P0 |
| Мерцание при печати исключающим ИЛИ | на BBC оно есть; на медленной машине заметнее | привязка стирания и печати объекта к кадру; у автора сайта есть разбор версии без мерцания — взять приём |
| Шрифт BBC из ПЗУ машины | чужая графика | свой шрифт 8×8 |
| Права | код © Acornsoft, комментарии © Mark Moxon, репозиторий без лицензии | `orig/` в git не входит; открытая публикация — решение владельца до выпуска |
