# Перенос процедуры 6502 → i8080: правила и образец

Образец — `v06c/src/arith.asm` (T06). Стенд — `v06c/tools/pair.mjs`, пример теста — `v06c/test/t06.mjs`.

## Что считается «перенесено»

После вызова с одним и тем же входом на Векторе и в эталоне равны: **A, X, Y, перенос и все рабочие области**
(нулевая страница, T%, K%, WP). Так проверяется и результат, и побочные записи (`T`, `T1`, `U`, `P`…), на
которые в коде BBC нередко рассчитывает вызывающий. Отступление допускается только названное в заголовке
процедуры и в тесте (`skip`, `noreg`) — так сделано в процедурах рисования (`v06c/src/line.asm`).

## Соответствие

| 6502 | i8080 |
|---|---|
| A | A |
| X | B |
| Y | C |
| перенос C | CY — **тот же смысл на выходе процедуры** |
| ячейка `ИМЯ` | `ИМЯ` из `v06c/src/bbc_vars.inc` (`%` → `_`; `P` → `P_`, `R` → `R_`) |
| `LDA ТАБЛ,Y` | `ld hl, ТАБЛ` / `ld b, 0` / `add hl, bc` / `ld a, (hl)` (если X дальше не нужен) |
| D, E, H, L | свободны: внутри процедуры что угодно, на выходе не сравниваются |

Имена процедур — как на BBC. Внутренние метки — строчными с префиксом процедуры.
Мнемоника — Z80 в пределах i8080 (`sjasmplus --i8080`): нет `jr`, `djnz`, `ex af`, `exx`, `ix/iy`, команд с
префиксами `CB` и `ED` (значит, нет `rl r`, `srl`, `bit`, `sbc hl`, `ldir`, `neg`). Сдвиги — только
`rlca, rrca, rla, rra` над A и `add a, a`, `add hl, hl`.

## Ловушки

1. **Перенос при вычитании обратный.** 6502: после `SBC`/`CMP` C = 1, если заёма нет (A >= операнд).
   i8080: после `sub`/`sbc`/`cp` CY = 1, если заём есть (A < операнд). Поэтому `CMP n : BCC m` → `cp n` /
   `jp c, m`, а `BCS` → `jp nc`. Если перенос после сравнения идёт дальше в сдвиг (`ROL`) или в результат —
   его надо перевернуть (`ccf`) или выставить явно (`scf`, `or a`).
2. **`SBC` на 6502 вычитает ещё и (1 − C).** Перед `SBC` почти всегда известно, чему равен C: если C = 1 —
   это `sub`, если C = 0 — вычитается на единицу больше.
3. **Логические команды i8080 (`and, or, xor`) сбрасывают CY**, на 6502 `AND, ORA, EOR` перенос не трогают.
   Если перенос должен пережить `ORA`, его надо восстановить (см. `ADD` в образце).
4. **`inc r`, `dec r`, `inc (hl)` не трогают CY** (как `INX`, `DEC` на 6502), `inc hl`, `dec hl` не трогают
   флаги вовсе. `ld` флаги не меняет. `cpl` флаги не меняет.
5. **`ROL A` → `rla`, `ROR A` → `rra`** (через перенос). `ASL A` → `add a, a`. `LSR A` → `or a` / `rra`.
   `ROL ячейка` → `ld a, (ячейка)` / `rla` / `ld (ячейка), a`.
6. **Флаги N и Z после возврата** не сравниваются. Если вызывающий на BBC ветвится по ним сразу после `JSR` —
   на i8080 он должен поставить `or a` сам.
7. **Флаг переполнения V** на i8080 отсутствует (`BIT`/`BVS` — явной проверкой бита; `DORND` его не возвращает).
8. **Число, зашитое в цикл как сторож** (`LDX #254 : STX T1 … ROL T1 : BCS`), — восемь шагов; на выходе в
   ячейке частное, перенос 0.
9. Точное умножение 8×8 уже есть: `mul8` (HL = E·A). Если процедура BBC считает точное произведение — зовите
   его, а побочные записи (`T`, `T1`, X = 0, перенос) выставьте, как в `MULT1`.

## Цена команд на Векторе

Каждая команда занимает число тактов, кратное четырём: `ld r, r` и `inc r` — 8, `add a, r` — 4, всё через
`(hl)` — 8, `ld a, (nn)` и `ld (nn), a` — 16, `jp` — 12, `call` — 24, `ret` — 12, `add hl, hl` — 12,
`push` — 16, `pop` — 12. Обращение к ячейке по адресу втрое дороже регистра: частые значения держать в
регистрах.

## Порядок работы

1. Прочитать процедуру BBC, выписать: входы (регистры, ячейки), выходы, побочные записи, чему равен перенос на
   выходе на каждом пути.
2. Добавить запись в тест (вход — генератор с краями: 0, 1, 127, 128, 255).
3. Написать процедуру, собрать `sh v06c/build.sh` (ни одной команды Z80, ни одного предупреждения), запустить
   тест. Сообщение о расхождении называет вход, регистр или ячейку.
