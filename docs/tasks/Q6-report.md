# Q6. Отчёт: оборудование (`EQSHP`, `eq`, `prx`, `qv`) — 6502 → i8080

## Что сделано

`EQSHP`, `eq`, `prx` (с входом `prx_m1` = `prx-3`), `qv` и таблица `PRXS` перенесены в
`v06c/src/equip.asm`. Изменён только этот файл.

Соответствие: A = A, X → B, Y → C; ячейки — из `bbc_vars.inc`. Перенос на выходе процедур —
как на BBC (`gnum`, `LCASH` уже возвращают «bbc-овский» перенос).

Приёмы переноса:

- `CMP #n : BNE` — цепочка `et0…etB` перенесена так, чтобы A (номер предмета) доживал до своего
  сравнения. На BBC номер живёт в A и переживает вызовы только потому, что его грузят заново
  (`LDA #4`, `LDA #5`); регистры Вектора для «постоянного хранения» не годятся — `DELAY`/`TT27`
  внутри `TT217`/`prq` крутят D/E/H/L между проходами сценария. Поэтому в каждом блоке, где идёт
  проверка флага по X/Y (`LDX cell : BNE pres`), после `or a` грузится **константа блока**
  (`ld a, N` — `ld` флаги не меняет, результат сравнения жив): и на переходе в `pres`, и на
  fallthrough A равен тому же, чему на BBC.
- `eq`: `BCS c`, а `c` — это просто `ret` (в ROM метка `c` совпадает с `RTS` внутри `prx`):
  при хватке денег возврат с **неизменённым** A; `SEC : SBC #1` в `eq` — мёртвый код, он работает
  только при входе `prx-3`. Нехватка: `ld a, 197 / call prq / jp err` (в `err` не возвращаемся,
  стек правит `MLOOP`, как на BBC).
- `prx`: `ASL A : TAY : LDX PRXS,Y : LDA PRXS+1,Y : TAY` → `add a, a`, индекс через `add hl, bc`
  (без `ldir`/`ix`); на выходе B — младший байт цены, C — старший.
- `LDY cell : BEQ/BMI` — значение грузится в A, копируется в C, флаги ставит `or a`; A потом
  перезагружается константой (флаги `ld` не трогает).
- `LDY LASER,X` / `STA LASER,X` — адрес как `ld hl, LASER` + `ld a, b / add a, l / ld l, a`
  (X ≤ 5, переноса из младшего байта нет).
- `PHA/PLA` → `push af / pop af` + `or a` для `BNE`.
- Цена топлива: `(70 − QQ14) · 2` → `sub`/`add a, a`, запись в `ld (PRXS)` (младший байт слова 0).
- Печать цены: `scf` прямо перед `call TT11` (между ними только `ld`, флаги не меняют).

## Что было трудно (и где текст задачи расходился с эталоном)

1. **Текст задачи обрезал `qv`.** В кассетном исходнике (`elite-source.asm`, `.qv2`) после
   `JSR TT217` идёт `SEC : SBC #'0' : CMP #4 : BCS qv3 : TAX : RTS` — `qv` возвращает в X номер
   вида 0..3, а не знак клавиши. С переносом «как в тексте» эталон на проходе 83 покупал лазер в
   `LASER+0x31`, а Вектор — в `LASER+1`. После переноса хвоста расхождение ушло.
2. **Метка `c` в `eq`** — не `SEC : SBC #1`, а `RTS` (проверено по ROM эталона: `BCS` из `eq`
   попадает ровно в `RTS` конца `prx`). Первый вариант портил A (`dec a`), и вся цепочка `et*`
   уезжала не в свою ветку (проход 95: лишний `MCASH`, деньги не сходились).
3. **Хранение номера предмета в E** (идея «регистр-хранилище вместо A») — провалилась: `E` гибнет
   внутри `DELAY` в цикле ожидания `TT217` между проходами сценария. Заменено на константы блока
   (см. выше) — это и есть то, что делает BBC (`LDA #4`/`LDA #5`).
4. i8080 не имеет команд `ld (nn), r` и `ld r, (nn)` — sjasmplus часть таких форм собирает молча
   с усечением адреса (предупреждение), часть отвергает; все такие места сведены к `ld hl, nn` /
   `ld (hl), r` и `ld a, (nn)` / `ld r, a`.

## Размер

По листингу сборки (`v06c/build/elite_t.sym`): `EQSHP = 0x49FA`, `PRXS = 0x4C39` —
весь файл занимает 0x23F = **575 байт**, из них код 551 байт и таблица `PRXS` 24 байта.
