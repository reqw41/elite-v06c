# T12, T13. Трассировка побочных записей и первое переписывание горячего — отчёт (07.10.2026, архитектор)

## T12. Кто читает побочные записи

`node tools/oracle/liveness.js launch [процедура …]` — трассировка эталона на сценарии `launch` (525 проходов:
заставки, станция, взлёт, полёт, огонь). Для каждой записи в нулевую страницу запоминается процедура-писатель;
чтение той же ячейки другой процедурой до следующей записи считается «чужим». Полный вывод —
`docs/research/liveness_launch.txt` (853 строки).

Доказано (для этого сценария): у рабочих записей `T`, `T1`, `U` (`ADD`, `MULT1`, `MU11`, `MVT1`, `TIS1`),
`P` у `FMLTU`, `Q, R, S, T` у `LL51`, `P, Q, R, S, YSAV` у `LOIN` чужих читателей нет. Результаты (`P` у
`MULT1`, `K` у `DVID3B2`, `R` у `LL28`, `XX12` у `LL51`) читаются, как и должны.

Гипотеза: то же верно в бою, на рынке и на картах — сценарий их не покрывает. Перед тем как убирать запись в
процедуре, которая зовётся оттуда, трассировку надо повторить на сценариях T03.
