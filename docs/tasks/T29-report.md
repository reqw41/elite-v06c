## Пробовал и откатил

1. **Полная перепись `STARS1` по смыслу** (все умножения через `mul8`, пропуск `P`/`Q`/`R`/`S`/`XX`/`YY`): расхождение координат пыли и `RAND` (неверный перенос в `KILL1`). Откатил до точечной замены `MLU*`/`MLS*`/`MUT2`.
2. **Убрать запись `T` в `PIXEL2` и `T1` в `st_mults` одним шагом** — после правки сверка `STARS1` красная; откатил `stars.asm` к коммиту с рабочим `ADD`. Выигрыш от мёртвых записей в пыли отдельно не доказан.
3. **Рисовать планету только при изменении картинки** — уже откатывали в T28; не повторял.

## Почему не до 450 000

Профиль после шагов всё ещё плоский; главные доли (`docs/research/profile_flight_v06c.txt`):

| доля | процедура |
|---|---|
| 24,9 % | `LOIN` (короткие отрезки планеты/прицела; наклон уже из таблицы T28) |
| 11,6 % | `STARS1` (тело цикла; обёртки убраны, остаётся арифметика и `PIXEL`) |
| 9,6 % | `mul8` |
| 6,2 % | `BLINE` |
| 5,0 % | `PLS22` |
| 3,1 % | `ADD` / `MVS5` |

До цели нужно ещё ≈27 600 тактов. `LOIN` + `mul8` + остаток пыли ≈ 46 % прохода; без ослабления сверки или приближённой арифметики (`-DFAST` в полёте даёт ~1 %, см. T28) запас на точной сборке — единицы процентов за шаг, не 6 %.

## Гипотезы (не доказано)

1. **Цикл `LOIN` по смыслу ещё раз** (короткие отрезки: меньше подготовки `lx_tab`/`ly_*`) — оценка 3–6 % прохода.
2. **`MVS5`/`MVS4` в регистрах** — 3 %+3 % профиля; 1–2 % прохода.
3. **`PIXEL`/`PIXEL2` без лишних ячеек** (`PIXEL2 T` мёртв по liveness) — доли процента; нужна аккуратная сверка пыли.
4. **Более агрессивный `STARS1`** (не писать `YY`/`XX` между шагами, держать в регистрах до `ADD`) — 1–2 %, если довести полный перенос без поломки переноса в `KILL1`.
5. До скорости BBC на этой сцене на точной арифметике не дойти: 6502 при 2 МГц здесь примерно вдвое быстрее i8080 при 3 МГц с тактами Вектора (см. T28).
