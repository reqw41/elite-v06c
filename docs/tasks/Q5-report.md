## Что перенесено и как

- **LL38** — `PHA/PLA` заменены сохранением A в D (pop af вернул бы старые флаги).
  Перенос на выходе: знаки совпали — из `ADC R`; `R >= Q` — 0 (`or a`); `R < Q` — из
  `ADC #1`: `cpl` (флаги не трогает) + `or a` (на BBC перенос входа = 0) + `add a, 1`.
- **TIS2** — цикл 8 шагов со сторожем FEh: в `ROL T` попадает перенос 6502 (1 при
  вычитании — `scf` перед `rla`; 0 при отказе — `or a`). Остаток на время сдвига лежит в D.
  Хвост `LSR A : LSR A : STA T : LSR A : ADC T` — через `rrca + and 0x7F`; перенос от
  последнего сдвига = бит 2 старого T = бит 0 нового T, сложение `T>>3 + T>>2 + бит 0`.
  Путь `TI4` выходит с `scf` (на BBC BCS ушёл при переносе 1, AND/ORA его не тронули).
- **DVIDT** — `ASL P : ROL P+1` и оба `ROL` в цикле идут через A с сохранением остатка в D;
  перенос `ROL P+1` (бит 7 старого значения) живёт до `ROL A` следующего шага (`ld` флаги
  не меняют). `ASL Q : LSR Q` дают в памяти `Q & 01111111b`, а перенос от `LSR Q` всегда 0
  (удвоенное Q чётно) — с ним входит первый `ROL A`. `ORA T` на выходе разведён на два
  хвоста (`or` на i8080 сбрасывает CY, на BBC — нет), перенос выхода — из последнего `ROL P+1`.
- **LL129** — `PHA/PLA` снова через регистры (E — входное S). Перенос входа для пути `BPL`
  сохраняется в бите 7 L двумя командами (`ld l,0 : jp nc : ld l,0x80`) — единственный
  надёжный способ перенести CY в данные на этом стеке. Отрицательный путь: `R = cpl(R)+1`
  (CY = «R = 0» — ровно перенос 6502 после `SEC : SBC R`), затем `cpl : adc a, 0`.
  Финальный `EOR XX12+3` — двумя хвостами с `scf`, ORA на BBC перенос не трогает.
- **LL61** — счётчик `LSR A : INX : CMP Q : BCS` считает в X; `JSR LL28` — вызов
  `LL28_4` (цикл гарантирует A < Q). В цикле `LL64` перенос на выход — из `ROL U`
  (бит 7 старого U), он сохраняется в бите 7 E и возвращается через `rlca`.

## Ловушки, найденные по ходу (вне списка задачи)

1. **`BMI` после `ROL U` смотрит на бит 7 результата `ROL`, а не на A** — на 6502
   `ROL ячейка` меняет N и Z. Это ловит тест: A=42, Q=218, U=118: A после `ASL` = 48
   (бит 7 = 0), но `ROL U` даёт 236 (бит 7 = 1) — ветка на LL84 берётся.
2. **Эмулятор Вектора: `RLC` (`rlca`) не доносит старый перенос в бит 0 A**
   (в `i8080.js` обработчик 0x07 подставляет уже новый CY), в отличие от `RAL/RRC/RAR`.
   Поэтому «сохранить CY в бит 0 через rlca» здесь невозможно — перенос в данные
   переносится только ветвлением (`ld r,0 : jp nc : ld r,0x80`), а обратно читается `rlca`
   (CY из бита 7 работает верно).
3. **Эмулятор Вектора: `RAL` (`rla`) не выставляет SF** — `jp m` после `rla` берёт
   устаревший признак знака; бит 7 результата `ROL U` проверяется через `rlca` + `jp c`.
4. Ошибкоопасное место переноса: `ld hl, ЯЧЕЙКА` для `xor (hl)`/`cp (hl)` портит H:L —
   если в L лежал сохранённый перенос, он теряется (поймано трассировкой по шагам).
