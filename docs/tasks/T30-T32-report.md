# T30–T32. Экраны станции: карты, данные о системе, рынок, груз, покупка и продажа — отчёт (07.10.2026, архитектор)

Ветка `station` (worktree `../elite-v06c-st`), чтобы не мешать задаче T29 в основном каталоге.
Код: `v06c/src/charts.asm` (T30), `v06c/src/market.asm` (T31); данные — `v06c/data/qq23.asm` (товары),
таблица знаков клавиш в `v06c/data/keys.asm`.

Проверка:
```sh
sh v06c/build.sh && sh v06c/build.sh -DSCHED
node v06c/test/t30.mjs && node v06c/test/t31.mjs && node v06c/test/t27.mjs trade
```

## Доказано

### Сценарий `trade` — 120 точек сверки от включения (`node v06c/test/t27.mjs trade`)

Обе заставки → станция → цены (f7) → покупка (f1): две единицы первого товара, одна — второго, выход →
груз (f9) → продажа (f2): первый товар — да, дальше нет → дальняя карта (f4), перекрестие вправо и вверх, D →
ближняя карта (f5), перекрестие влево и вниз, D → данные о системе (f6) → статус (f8).
В каждой точке обзор, панель и рабочие области равны эталону. Точки сверки стоят и внутри ввода с клавиатуры —
на ожидании отпускания и нажатия клавиши в `TT217`.

## Исправление эталона

У настоящего BBC ячейка `TRTB%` указывает на таблицу перевода клавиш в знаки в ПЗУ системы (`&F02B` у OS 1.20,
значение снято с jsbeeb). В стенде `tools/oracle/bbc.js` она была нулевой: ввод числа и ответы Y/N в эталоне
читали бы мусор. Исправлено; `tests/golden/launch.json` перезаписан (в сценарии `launch` изменились только
хеши нулевой страницы из-за этих двух байт), сверка с jsbeeb (`xcheck.mjs`) — как раньше, только `LASCT`.

## Оговорки

- **Оборудование (`EQSHP`, f3) не перенесено** — заглушка. Сохранение (`@`) — тоже.
- На Векторе знак по клавише берётся из своей таблицы `kb_ascii` (из `tools/convert/keys.py`); она сверена с BBC
  только на клавишах, которые нажимает сценарий (цифры, RETURN, Y, N, Q).
- Запасы товаров `AVL` сейчас берутся из командира по умолчанию; `GVL` (пересчёт при прибытии в систему)
  перенесена и проверена, но зовётся только после прыжка, которого ещё нет.
- Образ 28,4 КБ, свободно 16,4 КБ.
